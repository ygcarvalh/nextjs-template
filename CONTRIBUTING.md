# Contributing

## Setup

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

Node 22.13+ and pnpm 9+. `.nvmrc` and the `packageManager` field pin both.

## Before you push

```bash
pnpm verify   # typecheck, lint, coverage, build
```

The hooks run a subset automatically: `lint-staged` on commit, `commitlint` on
the message, and typecheck plus tests on push.

## Commits

Conventional Commits, header only, 50 characters or fewer, imperative mood, no
trailing period. Allowed types: `feat`, `fix`, `docs`, `style`, `refactor`,
`test`, `chore`, `perf`. Put the reasoning in the pull request instead of the
commit body.

## Layout

Each feature owns its types, server code, components, and tests:

```
src/features/<name>/
  index.ts          # client-safe exports
  types.ts          # zod schemas + inferred types
  server/
    index.ts        # server-only exports and the composition point
    *-repository.ts # the port
    *-service.ts    # use cases, which take the port
  components/
```

Two rules hold this together.

Components must not import a feature's server layer, which Biome enforces
through `noRestrictedImports`. Import a Server Action, call a route handler, or
take the data as a prop from a Server Component instead. Server Actions live in
`server/*-actions.ts` and are the one allowed exception.

Services depend on a port rather than on a concrete store, so swapping the
in-memory repository for a database should touch the adapter and one binding and
nothing else.

Route handlers under `src/app/api` are HTTP adapters. Authenticate, parse,
delegate, map the result to a status code. Rules belong in the service.

## Tests

Tests sit next to the code they cover. The extension picks the environment:

- `*.test.ts` runs in node, for server code
- `*.test.tsx` runs in jsdom, for components

The split is load bearing. `@t3-oss/env-nextjs` decides whether server variables
are readable by checking for a `window`, so a server module tested under jsdom
refuses to hand over `SESSION_SECRET`.

Coverage thresholds are enforced and sit just under the current numbers. Files
excluded from coverage are the ones the Playwright suite covers for real: route
entry points, boundaries, and Server Actions.

```bash
pnpm test              # watch-free unit and component tests
pnpm test:watch
pnpm test:coverage
pnpm test:e2e          # builds, starts, and drives a real browser
```

Playwright runs against the production build rather than the dev server, and
serially, because the demo repository is one in-process array.

## Styling

Colors, radii, and fonts are tokens in `src/app/globals.css`. Change them there
rather than in components. `src/components/ui/**` is generated by the shadcn CLI
and is excluded from linting.

One gotcha: when applying `buttonVariants()` to something that is not a
`Button`, such as a `Link`, wrap it in `cn()`. Without it the base
`border-transparent` and the variant's `border-border` both survive and the
border disappears.

```tsx
<Link href="/notes" className={cn(buttonVariants({ variant: "outline" }))}>
```

## Adding a shadcn component

```bash
pnpm dlx shadcn@latest add <component>
```
